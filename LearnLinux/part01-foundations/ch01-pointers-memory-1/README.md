# 第 1 章 指针与内存（一）：地址、解引用、指针与数组

## 1. 从变量到地址

程序运行时，数据住在内存里。可以把内存想象成一排带编号的储物柜：**每个字节是一个柜子，编号就是地址**。

当你写下：

```cpp
int a = 42;
```

发生了两件事：编译器在内存里划出 4 个字节（`int` 的大小）的空间，并把这块空间**起名叫 `a`**；然后把 42 存进去。变量名只是给人看的别名，机器真正认的是地址。

想知道一个变量的地址，用**取地址运算符 `&`**：

```cpp
&a   // a 的地址
```

`ex01_address.cpp` 打印了三个不同类型变量的地址（某次运行的结果，地址数值每次运行都可能不同，看关系即可）：

```
a: value=42,  address=0x7fff9e9422d4
b: value=3.140000,  address=0x7fff9e9422d8
c: value=X,  address=0x7fff9e9422d3
```

地址是十六进制数。注意三个地址互不相同、相距很近——它们是同一次函数调用里相邻分配的局部变量。

## 2. 指针变量：专门存地址的变量

地址本身也是一种值，需要变量来存。**指针变量就是专门存放地址的变量**：

```cpp
int* p = &a;   // p 里存的是 a 的地址，读作 "p 指向 a"
```

声明时要写明"指向什么类型"：`int*` 表示"指向 int 的指针"。类型必须对得上——你不能把 `double` 的地址塞进 `int*`，编译器会直接报错。这不是啰嗦，第 4 节你会看到类型决定了指针的两件大事。

指针变量自己有多大？`ex01_address.cpp` 的后半段测了：

```
sizeof(int*)    = 8
sizeof(double*) = 8
sizeof(char*)   = 8
```

**无论指向什么类型，指针本身都是 8 字节**（64 位系统）。原因很直白：它存的只是一个地址编号，编号的位数由机器决定，与所指的东西无关。

## 3. 解引用：顺着地址找过去

有了地址，怎么用？**解引用运算符 `*`** 表示"顺着这个地址，找到那块内存"：

```cpp
int score = 60;
int* p = &score;
*p = 95;        // 把 95 写进 p 所指的那块内存，也就是 score 本身
```

注意 `*` 的两种出场要分清：**声明里的 `int* p` 是在声明类型**（指向 int 的指针）；**表达式里的 `*p` 是解引用**（取 p 所指的值）。这是初学时最容易混的一点。

`ex02_deref.cpp` 的运行结果：

```
before: score = 60
read via *p: 60
after:  score = 95
```

明明没有直接给 `score` 赋值，它却变成了 95——因为 `*p` 和 `score` 是同一块内存的两个入口。这正是函数的参数传递、回调函数等机制的地基：想让函数改到外面的变量，就把地址交出去（练习 3 就练这个）。

## 4. 指针与数组

数组是一段**连续**的内存。`int arr[5]` 就是 5 个 int 挨在一起，共 20 字节。这里有指针最重要的一条规则：

> **数组名在表达式中会退化为指向首元素的指针**，即 `arr` 等价于 `&arr[0]`，并且 `arr[i]` 完全等价于 `*(arr + i)`。

`ex03_pointer_and_array.cpp` 的关键输出：

```
arr     = 0x7fff1e10c820
&arr[0] = 0x7fff1e10c820        ← 两者相同，验证了"退化"
&arr[0] = 0x7fff1e10c820
&arr[1] = 0x7fff1e10c824        ← 相差 4
&arr[2] = 0x7fff1e10c828        ← 又相差 4
...
(&arr[4] - &arr[0]) = 4 elements   ← 指针相减得到的是元素个数
arr[2] = 30, *(arr + 2) = 30       ← 两种写法结果相同
```

顺带回答了"指针为什么要有类型"：因为 **`p + 1` 前进的不是 1 个字节，而是 1 个元素的大小**。`int*` 每步 4 字节，`double*` 每步 8 字节，`char*` 每步 1 字节。编译器靠指针的类型才知道步长多大、解引用时该取几个字节拼成一个值。

## 5. 指针运算与边界

`ex04_pointer_arith.cpp` 用指针遍历数组求和，这是 C 风格代码里最常见的指针用法骨架：

```cpp
int* end = arr + 5;                    // 尾后指针
for (int* p = arr; p != end; ++p) {
    sum += *p;
}
```

运行结果：`sum = 64`（3+7+11+18+25），且 `p0 + 1` 的地址确实前进了 4 字节。

这里埋着一条必须记住的边界规则：

> **`arr + 5` 这种"最后一个元素的下一个位置"叫尾后指针。它是个合法地址，可以拿来比较（比如判断循环结束），但绝对不能解引用**——那块内存不属于这个数组。把指针移出 `[arr, arr+5]` 这个范围、或者解引用尾后指针，都是未定义行为：程序可能崩溃，也可能"看起来正常"却在别处埋雷。

指针的坑大多出在边界上。下一章我们会专门看多级指针、堆上的内存，以及野指针、悬垂指针这些"出事现场"长什么样。

## 示例代码：构建与运行

```bash
cd examples
cmake -S . -B build
cmake --build build
./build/ex01_address
./build/ex02_deref
./build/ex03_pointer_and_array
./build/ex04_pointer_arith
```

核对要点：

- `ex01`：三个地址为十六进制且互不相同；三种指针的 `sizeof` 都是 8。
- `ex02`：输出依次为 60、60、95。
- `ex03`：`arr` 与 `&arr[0]` 地址相同；相邻元素地址差为 4；指针相减得 4；`arr[2]` 与 `*(arr + 2)` 都为 30。
- `ex04`：`sum = 64`；`p0 + 1` 比 `p0` 大 4 字节。

> 验证记录：以上输出由作者在 Ubuntu 24.04 / GCC 13.3 / CMake 3.28 环境下以 `-std=c++11 -Wall -Wextra` 构建实测（零警告），日期 2026-10-22。地址数值每次运行会变，核对关系而非数值。
