# 第 6 章 练习参考答案

## 练习 1

运行结果是**重复释放（double free）**：`p` 与 `q` 是同一地址的两个副本，`delete` 执行两次。ASan 会以 `attempting double-free` 当场拦截（第 2 章验过同类现场）。根因是裸指针不携带所有权信息——编译器眼里 p、q 只是两个数字，谁也不知道自己"是不是主人"。

换 `unique_ptr` 后，结构上就写不出这段事故：

```cpp
std::unique_ptr<int> makeValue() {
    return std::unique_ptr<int>(new int(42));
}

int main() {
    std::unique_ptr<int> p = makeValue();
    // int* q = p;              // 编译不过：unique_ptr 不能拷贝
    std::unique_ptr<int> q = std::move(p);   // 只能显式转移，之后 p 为空
    return 0;   // q 出作用域自动释放，且只释放一次
}
```

要点：不是"程序员小心一点"，而是**让错误写法根本无法通过编译**——这正是把所有权写进类型的价值。

## 练习 2

| 步骤 | 计数 | 说明 |
|---|---|---|
| 1 | 1 | a 独自持有 |
| 2 | 2 | b 拷贝自 a，共享 |
| 3 | 3 | c 再拷贝一份 |
| 4 | 2 | a 放手，还剩 b、c |
| 5 | 1 | c 随作用域销毁，只剩 b |
| 6 | **0，对象在此销毁** | b 放手，最后一个主人离开 |

关键点：对象何时销毁只看计数归零的时刻，与"哪个变量先创建"无关；`reset()` 只是该指针自己放手。

## 练习 3

见 `ex03_datablock.cpp`（已编译验证：created 一次、destroyed 一次，转移后源断言为空）。

要点：工厂按值返回 unique_ptr 是所有权的"发货"；main 里 `std::move` 是"过户"；断言源为空是给转移上的保险丝。

## 练习 4

见 `ex04_add_move.cpp`（已编译验证，输出 `copies=1 moves=1`，被移动后源 size 为 0）。

要点：移动构造三件事——接管指针、把源指针置 NULL、把源 size 清零；少了置空一步，源对象析构时就会把已经过户的内存 delete 掉，重演练习 1 的事故。另外注意移动构造的 `noexcept`：加上它，容器才敢用移动（见练习 5b）。

## 练习 5

(a) 因为 weak_ptr 不保证对象还活着。单线程下同样有此问题：你刚检查完"对象还在"，在解引用之前，持有最后一个 shared_ptr 的那方可能已经放手（另一个作用域结束、一次 reset），对象随之销毁，你手里剩的便是指向已释放内存的途径——悬垂。`lock()` 的设计就是把"检查还活着"与"先占住一个计数"做成**一个不可分割的动作**：提升成功，对象至少活到这个临时 shared_ptr 用完为止；提升失败则明确告诉你对象已不在。把两步合成一步，竞态窗口从源头上关闭。

(b) 因为 vector 扩容要"先在新内存里安置好全部元素、成功了才弃旧"——若移动中途抛异常，元素已搬走一半、源数据已损毁，没法回滚；拷贝则搬坏了原数据还在。所以标准库的规则是：移动构造声明了 `noexcept`（保证不抛）才用移动，没保证就退回拷贝。加上 noexcept 等于向容器出具"搬运绝不翻车"的承诺，它才敢走这条快路。
