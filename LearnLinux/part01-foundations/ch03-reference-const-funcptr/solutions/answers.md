# 第 3 章 练习参考答案

## 练习 1

输出：`a=9, b=8`

推演：`r` 是 `a` 的别名。`r = b;` 不是改绑，而是把 `b` 的值 8 赋给 `r` 背后的 `a`，`a` 变 8、`b` 不变；`++r` 再把 `a` 加到 9。`b` 从头到尾只被读过一次，所以还是 8。

最容易错在把 `r = b` 理解成"r 改指 b"——引用没有这个操作，绑定在声明那一刻就定终身了。

## 练习 2

**片段 A**：`limit` 是 const 常量，`&limit` 的类型是 `const int*`，把它赋给 `int* p` 等于允许通过 `p` 修改一个只读对象，编译器报错（invalid conversion from 'const int*' to 'int*'）。改法：`const int* p = &limit;`——但这样 `*p = 200` 本身又会被拦。结论：想改就别声明成 const；声明成 const，地址就只能交给同样带 const 的指针。

**片段 B**：`cp` 是顶层 const 的常量指针，指向在声明时就定死了，`cp = &z` 是给 const 变量赋值，编译错误。改法：如果确实需要改指向，就去掉顶层 const 用普通 `int*`；如果设计意图就是"永不改指向"，那第 3 行这种代码本身就不该存在。

读法复习：const 在 `*` 左边锁值（底层），在右边锁指向（顶层）。

## 练习 3

见 `ex03_clamp.cpp`（已编译验证，输出 `a=100, b=0, c=42`）。

为什么用引用：要改实参，所以不能按值；实参必然存在、不涉及改指向和指针运算，所以不必用指针，引用最干净；又因为要改，不能加 const。

## 练习 4

见 `ex04_transform.cpp`（已编译验证，输出 `1 4 9 16` 与 `-1 -2 -3 -4`）。

要点：`transform` 的第三个参数就是回调函数指针；它对回调内部做什么一无所知，只负责"挨个调用"——这正是回调解耦的味道：骨架与策略分离。

## 练习 5

1. **`int&`**：要改、必然存在、无需空状态与改指向，引用最合适。
2. **`const T&`**：只读加大对象——引用免拷贝，const 防误改，本教程后面读到的库代码里这是默认款。
3. **`T*`**：需要表达"可能没有"（`nullptr`）且要做指针运算遍历数组，引用做不到这两点。
4. **按值**：double 这类小对象复制成本忽略不计，按值最简单，还顺带与调用者的数据解耦。
