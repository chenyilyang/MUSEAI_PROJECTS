## 1. 引用：变量的别名

第 1 章我们用指针完成了"函数改外面的变量"。C++ 还给了一个更轻便的工具：**引用就是变量的别名**。

```cpp
int a = 10;
int& r = a;   // r 是 a 的别名
r = 25;       // 改 r 就是改 a
```

`ex01_reference.cpp` 的输出：

```
a = 25, r = 25
a = 99, b = 99
```

第二行是本章第一个易错点：当 `r` 已经是 `a` 的别名，`r = b;` **不是把 r 改绑到 b**，而是把 `b` 的值赋给 `r` 背后的那个变量（也就是 `a`）。所以 `a` 变成了 99，`r` 依然是 `a` 的别名。引用的规则就两条：

1. **声明时必须初始化**——别名得先有主。`int& bad;` 编译不过。
2. **一旦绑定，终身不换**——之后所有对引用的赋值、运算，都作用在它背后的变量身上。

把引用和指针对照着记：

| | 指针 | 引用 |
|---|---|---|
| 本质 | 存地址的变量 | 变量的别名 |
| 能否为空 | 可以是 `nullptr` | 不能（必须有指向的对象） |
| 能否改指向 | 可以 | 不能 |
| 使用语法 | 要 `*` 解引用、要判空 | 像变量本身一样用 |

经验法则：**能用引用就不用指针**——引用把"不能为空、不会改绑"写进了语言规则，代码更短也更安全；只有当"可能没有对象"（需要空状态）或"需要改指向、做指针运算"时才用指针。

## 2. const 与指针：四种组合一次说清

`const` 是 C++ 的"只读契约"：被它锁住的东西，谁改谁编译不过。它和指针组合出四种常见声明，诀窍是**从右往左读**，看 const 在 `*` 的哪一边：

```cpp
int* p1;                // 普通指针：指向、值，都能改
const int* p2;          // const 在 * 左边（底层 const）：锁住"所指的值"
int* const p3;          // const 在 * 右边（顶层 const）：锁住"指针的指向"
const int* const p4;    // 两边都锁
```

`ex02_const_pointer.cpp` 把四种各演示了一遍，非法操作都留在注释里（你可以取消注释，亲眼看看编译器怎么报 "read-only variable is not assignable" 这类错误——读报错也是本章的训练内容之一）。合法部分的运行结果：

```
x = 30, y = 2
*p2 = 2, *p4 = 30
```

记住两个高频场景就不容易乱：**函数只想读、不想改**调用者的数据时，参数写 `const T*` 或 `const T&`（下一节细讲）；**指针变量本身定下来就不换**时，给它加顶层 const。顶层/底层这对术语后面看库代码、看报错信息时还会遇到，先混个脸熟。

附带一条：`const int limit = 100;` 这样的常量，取地址得到的是 `const int*`，**不允许**赋给普通 `int*`——那等于把只读契约撕了，编译器会拦住（练习 2 第一处就是这事）。

## 3. 传参三式：按值、指针/引用、const 引用

把前两章和本章合起来，函数传参的选型就清楚了。`ex03_ref_params.cpp` 做了两组对照。

**第一组：swap 的指针版与引用版。**

```cpp
void swapByPtr(int* a, int* b);   // 调用：swapByPtr(&a, &b); 函数里满眼 * 和 &
void swapByRef(int& a, int& b);   // 调用：swapByRef(a, b);  就像在操作变量本身
```

两者效果相同（实测都是先换成 2,1，再换回 1,2)，但引用版在调用处和函数体里都更干净，而且天然排除了"传了个 nullptr 进来"的可能。要改实参、且实参必然存在——用引用。

**第二组：只读大对象，为什么用 const 引用。**

示例里的 `Big` 结构体带了拷贝计数，实测：

```
copies after byValue   = 1     ← 按值传参，实打实拷贝了一份
copies after byConstRef = 1    ← const 引用传参，计数没涨：零拷贝
```

按值传参会把整个对象复制一份进函数；对象一大就是纯浪费。`const T&` 同时解决了两件事：引用传递**不拷贝**，const 保证函数**不会（也不能）改**调用者的数据。所以经验法则补完：

- 要改实参 → `T&`（必然有对象）或 `T*`（允许为空/要改指向）；
- 只读，小对象（int、double 这种） → 按值，最简单；
- 只读，大对象 → `const T&`，默认选择，C++ 代码里满眼都是它。

## 4. 函数指针与回调

函数在内存里也有地址，于是函数也能被指针指着——**函数指针**：

```cpp
int add(int a, int b) { return a + b; }
int (*op)(int, int) = add;   // op 指向签名为 int(int,int) 的函数
op(6, 3);                    // 通过指针调用，结果 9
```

函数指针的声明长得吓人（名字被括号包住），实战中一般用类型别名把它变短。**用 C++11 的 `using` 给类型起别名**：

```cpp
using BinaryOp = int (*)(int, int);
BinaryOp op = add;
```

有了"函数可以存进变量、数组、参数"，两个经典用法就成立了（`ex04_func_pointer.cpp` 各演示一个，输出已实测）：

**（1）分发表**：把同签名的函数装进数组，按编号/操作码选一个来调：

```
6 add 3 = 9
6 sub 3 = 3
6 mul 3 = 18
```

**（2）回调（callback）**：函数 A 把"某个环节的具体做法"留给调用者以函数指针的形式传进来。示例里 `sortWith` 负责排序骨架，"谁该排前面"由回调决定，于是同一份代码传 `ascending` 得升序、传 `descending` 得降序：

```
1 2 4 7 9
9 7 4 2 1
```

回调是理解后面一切事件驱动机制的钥匙：操作系统的信号处理、网络库的"数据到达通知"、vsomeip 的消息处理函数注册，本质上都是"先把你的函数登记好，事情发生时我来调用它"。第 1 章埋的线在这里收口：**函数指针 + 地址传递，就是 C 语言世界里实现"插件化"的全部基础**，C++ 后面会用虚函数、lambda、std::function 把它包装得更好用，但地基是这一章。

## 示例代码：构建与运行

```bash
cd examples
cmake -S . -B build
cmake --build build
./build/ex01_reference
./build/ex02_const_pointer
./build/ex03_ref_params
./build/ex04_func_pointer
```

核对要点：

- `ex01`：两行输出分别为 `25, 25` 与 `99, 99`。
- `ex02`：`x = 30, y = 2`；`*p2 = 2, *p4 = 30`（取消注释里的非法行应逐个引来编译错误）。
- `ex03`：两次 swap 结果 `2, 1` 与 `1, 2`；拷贝计数在 byValue 后为 1，byConstRef 后仍为 1。
- `ex04`：计算结果 9、3、18；两行排序结果分别为升序与降序。

> 验证记录：以上结果由作者在 Ubuntu 24.04 / GCC 13.3 / CMake 3.28 环境下以 `-std=c++11 -Wall -Wextra` 构建实测（零警告），日期 2026-10-22。
