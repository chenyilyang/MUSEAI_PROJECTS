# 第 2 章 练习参考答案

## 练习 1

输出：`a=7, b=0`

推演：
1. `p` 指向 `a`，`pp` 指向 `p`。`**pp += 4` 顺着两级找到 `a`，`a` 变成 7。
2. `*pp = &b` 改的是 `p` 的指向——从这行起 `p` 不再指向 `a`，改指 `b`。此时 `a` 仍是 7，不受影响。
3. `**pp = 0` 顺着 `pp → p → b`，把 `b` 改成 0。

易错点：第 2 步改的是"指向"，不是任何变量的值；它之后 `**pp` 摸到的已经是 `b` 而不是 `a` 了。

## 练习 2

**错误 1：配对错误。** `arr` 是 `new int[10]` 分配的数组，必须用 `delete[] arr;` 释放。用 `delete arr;` 是未定义行为，可能造成堆损坏。

**错误 2：内存泄漏。** `q` 用 `new int(5)` 申请，函数结束前没有 `delete q;`。函数一返回，`q` 这个唯一的地址记录就没了，那块内存再也找不回来，直到进程结束。`process()` 若被反复调用（想想座舱里常驻服务的处理循环），内存会一路涨上去。

改对：

```cpp
void process() {
    int* arr = new int[10];
    // ... 使用 arr ...
    delete[] arr;

    int* q = new int(5);
    // ... 使用 *q ...
    delete q;
}
```

## 练习 3

见 `ex03_alloc_array.cpp`（已编译验证，输出 `1 2 3 4 5`）。

要点：参数检查放在分配之前；`*out` 的解引用配合括号 `(*out)[i]`；返回 `bool` 让调用者能判断成败，是 C 风格接口常见的做法。

## 练习 4

见 `ex04_clone_array.cpp`（已编译验证，输出 `src[0] = 1`、`copy[0] = 99`）。

要点：`src` 加 `const` 是在签名里就向调用者承诺"只读不改"，编译器会替你把关；副本是独立的一块堆内存，改它不影响原数组；谁拿到返回的指针，谁负责 `delete[]`。

## 练习 5

防得住的：置 `nullptr` 之后，**这一个指针**的误用变得可控——判空 `if (p)` 能拦住它；万一直接解引用空指针，程序会立刻明确崩溃（段错误），而不是访问一块被回收又被复用的内存、产生无声的错误数据。

防不住的：如果有**另一个指针**也指着同一块已释放的内存（别名副本），它手里存的还是老地址，置空第一个指针管不到它，它依然是悬垂指针。这说明真正的病根是"一块内存有多个指针在指、却没人说清谁负责释放"——这叫**所有权**问题，靠手动置空解决不了。第 6 章的智能指针就是来系统性解决它的：所有权写进类型里，释放自动发生，别名则用 `weak_ptr` 这种"能查岗、不续命"的形式存在。
