## 1. 多级指针：让函数"改指向"

第 1 章的练习里，`addTen(int* p)` 能改调用者的**变量值**。但如果函数要改的不是值，而是**调用者那个指针本身的指向**呢？比如：函数负责在堆上建好一个数组，把数组的地址交给调用者——它得修改调用者的指针变量。按同样的逻辑：想改什么，就把什么的地址交出去。想改一个 `int*`，就传 `int**`，即**指向指针的指针**。

先看解引用两级是什么感觉（`ex01_double_pointer.cpp` 前半段）：

```cpp
int x = 1;
int* p = &x;      // p 指向 x
int** pp = &p;    // pp 指向 p
**pp = 2;         // 顺着 pp 找到 p，再顺着 p 找到 x，把 x 改成 2
```

主场景是后半段的 `buildScores`：

```cpp
void buildScores(int** out, int n) {
    *out = new int[n];              // *out 就是调用者的指针，给它赋上新数组的地址
    for (int i = 0; i < n; ++i) {
        (*out)[i] = (i + 1) * 10;   // 括号不能省：先解引用，再下标
    }
}
```

调用方原本只有一个空指针 `int* scores = nullptr;`，把它的地址 `&scores` 传进去，函数返回后 `scores` 就指向填好 `10 20 30 40` 的数组了。运行输出验证无误：

```
x = 2
10 20 30 40 
```

记住这个模式——**"函数通过出参指针交还一块新资源"**在 C 风格接口和系统 API 里无处不在（想想各种 `createXxx(**out)` 风格的函数）。三级以上指针极少见，见到多半是接口设计出了问题，不用往深里钻。

## 2. 内存布局：栈与堆

一个运行中的程序，内存大致分这几片：

| 区域 | 放什么 | 谁管 |
|---|---|---|
| 代码段 | 机器指令 | 系统 |
| 数据段 | 全局变量、静态变量（整个程序期间都在） | 系统 |
| 堆（heap） | `new` 出来的内存，手动申请手动释放 | **你** |
| 栈（stack） | 局部变量、函数调用现场，函数返回自动回收 | 编译器 |

`ex02_heap_stack.cpp` 把四个区域各取了一个地址打印出来（某次运行）：

```
global  (data seg): 0x5cf6d5581010
static  (data seg): 0x5cf6d5581014     ← 与 global 紧挨着，同属数据段
local   (stack)   : 0x7ffdedf8013c     ← 栈在高地址区，明显是另一片
heap var (heap)   : 0x5cf7029f52b0     ← 堆又是另一片
```

栈和堆的根本区别是**生命周期与管理方式**：

- **栈**：局部变量随函数调用自动出现、随函数返回自动消失。不用你操心，但也因此**绝不能把栈变量的地址传出去给别人长期使用**——函数一返回，那块内存就被回收再利用，指针立刻悬垂（见第 5 节）。
- **堆**：`new` 出来的内存跨函数存活，直到有人 `delete`。`ex02` 里 `makeOnHeap` 返回的数组在 `main` 里照样能用，输出 `100 101 102`。代价是：释放的责任在你。

本教程先立一条约定：**谁 `new`，谁负责 `delete`**。第 6 章会看到，这条靠自觉的约定如何被 RAII 和智能指针变成自动机制。

## 3. new/delete 配对规则

只有两条，背下来：

```cpp
int* p = new int(5);      // 配 delete p;
int* a = new int[10];     // 配 delete[] a;
```

- `new` ↔ `delete`，`new[]` ↔ `delete[]`。**错配是未定义行为**，轻则堆损坏，重则崩溃，而且往往不在出错现场发作。
- 忘了 `delete` 叫**内存泄漏**：那块内存到进程结束前谁也用不了。短命的小程序无所谓，但座舱里的常驻服务一跑几个月，每秒漏一点就是事故——练习 2 就有这两类错误等你找。

## 4. void*：没有类型的指针

先认识一个特殊指针 `void*`：它能存放**任何类型**的地址，但因为它"不知道自己指向什么"，所以**不能直接解引用、不能做指针运算**，用之前必须先转回具体类型：

```cpp
int v = 123;
void* raw = &v;            // 任何地址都能存进 void*
int* p = (int*)raw;        // 用之前转回来
// *p == 123
```

现在只需眼熟它：它在系统编程里非常常见，凡是"先把地址/缓冲区传过去，类型以后再说"的接口（比如线程函数参数、通用读写缓冲）都用它，后面章节会反复遇到。

## 5. nullptr：为什么不用 NULL

C 时代用 `NULL` 表示空指针，但在 C++ 里 `NULL` 通常就是整数 `0`，会惹麻烦。`ex03_nullptr.cpp` 里有两个重载：

```cpp
void f(int);
void f(int*);
```

```
f(0);        → f(int) called
f(nullptr);  → f(int*) called
```

如果写 `f(NULL)`，编译器看到的是一个整数，命中的是 `f(int)`——甚至在某些定义下产生二义性报错。C++11 的 `nullptr` 是专门表示空指针的字面量，类型是 `std::nullptr_t`，只会往指针那边走，不会再被当成整数。

从这章起立规矩：

> **声明指针时立刻初始化；暂时不指向任何东西，就初始化为 `nullptr`。判空后再使用。**

第 1 章练习 2 里那个未初始化的野指针，就是反面教材。

## 6. 事故现场：悬垂指针

`examples/bad_01_dangling.cpp` 是本章反例（文件名带 `bad_`，不要模仿）：

```cpp
int* p = new int(42);
delete p;                    // 内存已归还，p 成为悬垂指针（还指着老地址）
printf("*p = %d\n", *p);     // 解引用悬垂指针：未定义行为
```

普通编译运行，作者实测的结果是：打印出一个莫名其妙的垃圾值，**退出码还是 0**——不崩、不报错，值已经错了。这就是未定义行为最阴险的样子：你的程序带病运行，问题会在别处以完全无关的面目爆发。

抓它的办法是检测工具。用 AddressSanitizer 重新构建：

```bash
g++ -std=c++11 -g -fsanitize=address bad_01_dangling.cpp -o bad_01_dangling
./bad_01_dangling
```

实测报告开头几行：

```
ERROR: AddressSanitizer: heap-use-after-free on address 0x502000000010
READ of size 4 at 0x502000000010 thread T0
    #0 ... in main .../bad_01_dangling.cpp:10      ← 出错在第 10 行（解引用）
freed by thread T0 here:
    #1 ... in main .../bad_01_dangling.cpp:8       ← 内存是在第 8 行（delete）释放的
```

报告把"在哪释放的、在哪误用的"都指出来了。以后写涉及堆内存的代码，拿不准时就用 ASan 构建跑一遍，这是成本最低的排雷手段。

**规避清单**（本章能落地的）：

1. 声明即初始化（`nullptr` 垫底）；
2. `delete` 之后立刻把指针置 `nullptr`，误用时至少会立刻崩在明处、判空也能拦住；
3. 想清楚每块堆内存"归谁释放"，一个所有者，不要多人乱删（同一块内存 `delete` 两次同样是事故）；
4. 能用栈和值语义解决的，别急着上堆。第 6 章的智能指针会把 1～3 大部分变成自动的。

```bash
cd examples
cmake -S . -B build
cmake --build build
./build/ex01_double_pointer
./build/ex02_heap_stack
./build/ex03_nullptr
# 反例单独用 ASan 构建（见正文第 6 节的命令）
```

核对要点：

- `ex01`：输出 `x = 2`，随后一行 `10 20 30 40`。
- `ex02`：四个地址分属不同区域（global 与 static 紧邻）；堆数组输出 `100 101 102`。
- `ex03`：依次输出 `f(int) called`、`f(int*) called`、判空提示。
- `bad_01`：普通构建的输出不可信（实测为垃圾值）；ASan 构建必须报 `heap-use-after-free` 并指向第 10 行与第 8 行。
