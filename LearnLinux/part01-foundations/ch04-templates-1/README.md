# 第 4 章 模板基础（一）：函数模板、类型推导与类模板

## 本章目标

学完这一章，你应该能做到：

- 说清模板解决什么问题，能写出简单的函数模板并用它；

## 1. 为什么需要模板

先看一个再普通不过的需求：求两个值的较大者。没有模板时，你得为每个类型写一份几乎一模一样的函数：

```cpp
int    maxInt(int a, int b)       { return a > b ? a : b; }
double maxDouble(double a, double b) { return a > b ? a : b; }
// 还有 long、float、字符串……逻辑全同，只是类型不同
```

逻辑只写了一遍，代码却要抄很多遍——抄写既枯燥又容易漏改。**模板就是给编译器的"代码生成图纸"：你把逻辑写一次，把类型留作参数；用的时候编译器按你给的类型现场生成那份代码。**

```cpp
template <typename T>
T maxValue(T a, T b) {
    return a > b ? a : b;
}
```

读法：`template <typename T>` 声明"T 是一个类型参数"；函数体里凡是写 T 的地方，生成时都换成实际类型。这个"按类型生成真正代码"的过程叫**实例化**。它发生在编译期，所以模板没有运行时开销——生成的就是你手写会写出的那份函数。

`ex01_func_template.cpp` 的实测输出：

```
int:    7
double: 2.500000
string: dds
mixed:  7.500000
```

int、double、string 三种类型共用一个 `maxValue`，这就是收益。

## 2. 类型推导：T 是怎么定下来的

调用 `maxValue(3, 7)` 时你没写 T，编译器**从实参反推** T 的过程叫类型推导。`ex01` 里藏了一个经典的坑：

```cpp
maxValue(3, 7.5);   // 编译报错！
```

两个参数都是 T，一个实参说 T=int，另一个说 T=double，推导冲突，编译器不会自作主张帮你统一。解法是**显式指定**：`maxValue<double>(3, 7.5)`——T 定死了，3 自动转成 double 再传入（输出 7.500000)。这条规则记牢：**推导要求所有同名参数给出一致的答案**。

推导规则的大头在"参数的传递方式怎么影响 T"。`ex02_deduction.cpp` 用 `sizeof` 和类型编码留下了实测证据（GCC 的类型编码：`i`=int、`Pi`=int*、`PKc`=const char*，仅作对照）：

**按值传参 `void f(T param)`：**

| 调用 | 推导出的 T | 证据与说明 |
|---|---|---|
| `f(x)`，x 是 int | int | sizeof(T)=4 |
| `f(cx)`，cx 是 const int | int | 顶层 const 被**丢弃**——反正是拷贝一份，const 不带过去 |
| `f(arr)`，arr 是 int[4] | int* | **数组退化**为指针，sizeof(T)=8 |
| `f("Linux")` | const char* | 字符串字面量是 const char 数组，退化后 const 保留（这是底层 const，不丢） |

**引用传参 `void g(T& param)`：**

| 调用 | param 的实际类型 | 证据与说明 |
|---|---|---|
| `g(x)` | int& | sizeof(param)=4 |
| `g(cx)` | const int&（T=const int) | const **保留**——引用不拷贝，必须尊重原对象的只读性 |
| `g(arr)` | int(&)[4] | **不退化**!sizeof(param)=16，与数组本体一致 |

对照第 3 章的 const 知识，这张表其实只在说一件事：**按值 = 复制一份新的，所以顶层 const 和"数组性"都留在原地；引用 = 本人的别名，所以一切都原样保留。**把这个图景装进脑子，推导题就不用死记了。

## 3. 类模板

模板同样能用在类上。`ex03_class_template.cpp` 有两个例子。

**多个类型参数**——信号值和它的单位，正好是一对异型数据：

```cpp
template <typename T1, typename T2>
struct Pair {
    T1 first;
    T2 second;
    ...
};
Pair<int, const char*> signal;   // 用的时候把类型填满，这才是一个真正的类型
```

注意：类模板**不能像函数那样靠构造参数推导 T**（C++11 时代如此，类模板参数必须显式写全；C++17 的 CTAD 才放宽，那是专题章的事）。`Pair` 本身不是类型，`Pair<int, const char*>` 才是。

**成员函数在类外定义**——类内声明了 `get()`，在类外补定义时，仪式比普通类多两样：

```cpp
template <typename T>
T Box<T>::get() const {
    return value_;
}
```

先写 `template <typename T>` 表明"我在给某个模板写成员"，函数名要写全 `Box<T>::get`——作用域里的 `Box<T>` 不能简写成 `Box`。这套写法后面看库源码时天天见，先在这里认全。

实测输出：

```
(2500, rpm)
Box<int> = 42
Box<string> = SOME/IP
```

## 4. 模板与普通函数同名：谁优先

当普通函数和函数模板同名、都能接这个调用时，顺序是（`ex04_overload_with_template.cpp` 实测）：

```
show(5);      → ordinary function        // 两边都精确匹配，普通函数优先
show(5.5);    → template function, T=d   // 模板精确推导 double；普通函数得把 double 转 int，代价更高
show("hi");   → template function, T=PKc // 只有模板接得住
show<>(5);    → template function, T=i   // <> 显式点名模板
```

浓缩成一句：**先比谁更合身（不需要转换的赢），同等合身时普通函数赢。**另外 `show<>(...)` 这种尖括号写法是"我就要模板版"的显式指令，读代码时见到别懵。

## 5. 模板代码为什么住在头文件里

顺着实例化想一步就通了：编译器要在**看到调用的地方**，拿着图纸（模板定义）现场生成代码。如果把模板定义单独放进一个 `.cpp`，使用它的另一个 `.cpp` 编译时根本看不见图纸长什么样，到链接期就会报 `undefined reference`——函数"只有声明、没有生成出来的实体"。

所以惯例是：**模板的声明和定义都写在头文件里**，谁用谁包含，图纸随叫随到。代价是包含它的每个文件都会生成自己用到的实例（链接器会合并重复份），以及编译变慢——这是模板的固有成本，心里有数即可。例外是"显式实例化"（把要用的类型提前在一个 `.cpp` 里全部生成），库工程里才会用，本章不展开。

## 示例代码：构建与运行

```bash
cd examples
cmake -S . -B build
cmake --build build
./build/ex01_func_template
./build/ex02_deduction
./build/ex03_class_template
./build/ex04_overload_with_template
```

核对要点：

- `ex01`：四行输出 7、2.500000、dds、7.500000；把注释中的冲突调用放出来应编译报错。
- `ex02`：byVal 四行类型编码依次为 i、i、Pi、PKc,sizeof 依次 4、4、8、8;byRef 三行 sizeof 为 4、4、16。
- `ex03`：三行输出 `(2500, rpm)`、`Box<int> = 42`、`Box<string> = SOME/IP`。
- `ex04`：四行依次命中普通函数、模板（double)、模板（const char*)、模板（int)。

> 验证记录：以上结果由作者在 Ubuntu 24.04 / GCC 13.3 / CMake 3.28 环境下以 `-std=c++11 -Wall -Wextra` 构建实测（零警告），日期 2026-10-22。
