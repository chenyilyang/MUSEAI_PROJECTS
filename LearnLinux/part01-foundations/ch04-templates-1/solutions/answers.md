# 第 4 章 练习参考答案

## 练习 1

| 调用 | 结果 |
|---|---|
| `maxValue(3, 9)` | ✅ T=int，结果 9 |
| `maxValue(3, 9.5)` | ❌ 推导冲突：第一个参数说 int，第二个说 double，编译器不替你猜 |
| `maxValue('a', 'z')` | ✅ T=char，结果 `'z'`（按字符编码比较） |
| `maxValue(3.0, 9)` | ❌ 同样冲突：double vs int |
| `maxValue<double>(3, 9)` | ✅ 显式指定 T=double，3 转成 3.0，结果 9.0 |

关键点：推导要求所有用到 T 的实参给出**同一个**类型；混类型不是不行，但要靠显式指定来终结推导。

## 练习 2

| 调用 | T | 理由 |
|---|---|---|
| `f(d)` | double | 按值，实参是什么就是什么 |
| `f(cd)` | double | 按值推导丢弃顶层 const（拷贝品不需要 const） |
| `f(name)` | char* | 数组退化为首元素指针；char 不是 const，退化后就是 char* |
| `g(d)` | double | 引用，param 为 double& |
| `g(cd)` | const double | 引用保留 const，param 为 const double& |
| `g(name)` | char[8] | 引用不退化，param 为 char(&)[8] |

和正文 ex02 的 int 版证据一一对应：按值三件事会丢（顶层 const、数组性），引用全保留。

## 练习 3

见 `ex03_clamp_template.cpp`（已编译验证，输出 100、2.500000、42）。

要点：三个参数同为 T，调用时三个实参类型要一致——`clampT(2.7, 0.0, 2.5)` 里三个都是 double 才能顺利推导；写成 `clampT(2.7, 0, 2.5)` 会重演练习 1 的冲突。

## 练习 4

见 `ex04_minmax.cpp`（已编译验证，输出 min=17, max=42 与 min=2.250000, max=3.500000）。

要点：类模板实例化时类型参数必须写全（`MinMax<int>`）；成员函数在类内定义时自动随类一同实例化，不需要额外的类外仪式。

## 练习 5

编译能过，是因为调用方拿着头文件里的声明，语法层面一切合法。但模板的**实例化**发生在"看到调用、且看得见定义"的地方：调用方的编译单元里只有声明、没有定义这张图纸，生成不出实体代码；`util.cpp` 那边虽然有定义，却没有任何调用点提示它该为哪些类型生成。于是两边都拿不出实体，链接期报 `undefined reference`。

通常的改法：把模板的定义也搬进头文件，让每个使用方都能就地实例化。另一个办法是在 `util.cpp` 里对要用到的类型做显式实例化，但那要求提前穷举所有用法，库工程之外很少这么干。
