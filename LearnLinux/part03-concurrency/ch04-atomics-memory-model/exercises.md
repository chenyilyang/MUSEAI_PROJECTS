## 练习 2（读代码：两步原子 ≠ 整体原子）

```cpp
std::atomic<int> g_seats(1);        // 只剩 1 个座位

// 两个线程各执行一次：
bool book() {
    if (g_seats.load() > 0) {       // 原子读
        g_seats.fetch_sub(1);       // 原子减
        return true;                // 订到了
    }
    return false;
}
```

每一步都是原子的，为什么仍可能把 1 个座位卖给 2 个人？画出出错的交错时序。给出两种修法：一种用 CAS 循环，一种利用 fetch_sub 的返回值（先扣后验，并说明超卖时如何回滚）。

## 练习 3（写代码：run-once）

用 atomic 状态机（0 未初始化 / 1 初始化中 / 2 已完成）+ CAS 实现 `ensureInit()`：无论多少线程并发调用，初始化函数体恰好执行一次，且每个调用者返回时初始化必已完成。8 个线程并发验证：初始化次数恰为 1，且所有线程读到的配置值都是初始化写入的 42。

## 练习 4（写代码：原子票号发生器）

用一个 `std::atomic<long>` + fetch_add 实现票号发放：8 个线程各领 1000 张票存入各自的桶，主线程合并排序后验证票号恰为 0..7999、不重不漏。说明 fetch_add 的返回值语义为什么让"占号+推进"一步到位。
