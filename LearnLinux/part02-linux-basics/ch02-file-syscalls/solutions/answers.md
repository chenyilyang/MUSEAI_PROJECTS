# 第 2 章 练习参考答案（第二部分）

## 练习 1

a=3，b=4，c=3，d=1。

一条规则解释全部：**open 总是分配当前最小的可用编号**，而 0/1/2 在进程启动时已被标准输入/输出/错误占用。a 拿最小的空位 3；b 拿 4；`close(a)` 把 3 释放回池子，c 于是又拿到 3；`close(1)` 把标准输出的 1 号位也放出来，d 便拿到 1——顺带说明一个真实教训：关错 fd 后，新打开的文件会顶替标准流的位置，后续往 1 号写日志就会写进文件里，这类"日志凭空消失"的灵异问题有一半是这么来的。

## 练习 2

- **片段 A**：用 errno 当成败判据，错。errno 的契约是"调用失败时给出原因"，从没承诺"成功时必然为 0"——成功路径上它残留着什么值（哪怕是调用前你自己清的零，也可能被函数内部的附带调用改掉）都不作数。把判据立在 errno 上就是立在沙子上。正确姿势：以返回值判成败（`fd < 0`），失败后再读 errno。
- **片段 B**：顺序错。失败后插入了一次日志调用才读 errno——日志函数内部的系统调用完全可能把 errno 改写（正文 ex02 实测：隔了几次 stdio 调用，errno 就从 2 变成了 22）。正确姿势：`if (fd < 0) { int saved = errno; ... }` 第一时间存下，之后爱记日志记日志，报错只用 saved。
- **片段 C**：把 0 和 -1 混为一谈，错。read 返回 0 是正经结局——读到文件尾/对端关闭，不是错误，此时 errno 无意义。正确姿势：`n < 0` 才看 errno，`n == 0` 按"读完"处理，`n > 0` 是实际字节数（还可能小于申请量，继续循环）。

## 练习 3

见 `ex03_copy_file.cpp`（已编译验证：5000 字节二进制内容拷贝后逐字节一致，`cmp` 亦无差异）。

要点：读循环以 0 为终点、以 -1 为失败；内层写循环把每次读到的 n 字节全部送出才罢休；出错路径上把已打开的 fd 关掉再返回。正文第 3 节的"没有一次到位"在这里就是全部的工作量。

## 练习 4

见 `ex04_tail.cpp`（已编译验证：16 字节文件取尾 10 字节正确；n 超过文件长度时输出全文）。

要点：`lseek(fd, 0, SEEK_END)` 先拿到大小，起点用 `max(size - n, 0)` 夹住下限，再 `SEEK_SET` 定位读出——内存占用只与 n 有关，与文件大小无关。日志排障时看大文件尾巴靠的就是这一手，而不是把几个 GB 的文件整个打开。

## 练习 5

(a) read 返回 0 表示"这个方向的尽头到了"，是正常结局而非失败：对普通文件，是偏移已到文件尾；对管道，是写端已经全部关闭且存量数据已被读空。它和 -1 的分工是：**0 = 没有更多了（永久），-1 = 这次没成（原因看 errno）**。把 0 当错误处理，会让每个正常读完的文件都报一次假警。

(b) 看 errno：等于 `EAGAIN`（非阻塞）是"现在没数据"，其余才是真错误。若把 EAGAIN 当致命错误，症状是程序在"还没人写入数据"的正常空窗期就直接退出（或疯狂报错误日志）——数据明明稍后就到，它却等都不等。非阻塞代码的正确姿势是：EAGAIN 时回去做别的事或稍后重试，这也是第四部分 epoll 把这件事系统化的原因。
