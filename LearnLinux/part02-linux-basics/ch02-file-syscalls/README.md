# 第 2 章 文件与系统调用（第二部分 · Linux 开发起步）

## 本章目标

学完这一章，你应该能做到：

- 说清系统调用与 C 库函数的区别，知道你的程序是怎样向内核"要服务"的；
- 熟练使用 open/read/write/close，并正确处理它们的返回值——包括"只搬了一部分"的情况；

- 用 lseek 做随机读与求文件大小，并说清它对管道为什么无效；
- 理解阻塞与非阻塞的差别，看懂 EAGAIN 并知道它不是失败。

**前置知识**：第二部分第 1 章（工具链）；第一部分的指针与缓冲区基础。本章起示例直接使用 POSIX/Linux 系统调用，头文件多为 C 风格（`<fcntl.h>`、`<unistd.h>`），代码仍按 C++11 编译。

## 1. 系统调用：程序与内核之间的门

你的程序运行在用户态，能做的事其实很少——想读写文件、收发网络、创建进程，都得**敲内核的门**。这扇门就是系统调用：`open`、`read`、`write`、`close` 这些函数看似普通，它们内部会陷入内核，由内核代为操作硬件与文件系统，再把结果带回来。

和它们相对的是**库函数**，比如 C++ 的 `std::fstream`、C 的 `fopen/fread`：它们不直接敲门，而是先在用户态替你攒缓冲、做格式化，最后仍然要通过系统调用落地。两层的区别在排障时至关重要：**库函数出错可能只是缓冲层的问题，系统调用的返回值与 errno 才是内核给的最终答复**。本章先把最底层这一层练扎实，之后网络、进程各章全是同一套路：系统调用 + 返回值 + errno。

## 2. 文件描述符：一个整数就是一把钥匙

在 Linux 里，一个被打开的文件（以及管道、socket、设备……）都用一个小整数表示，叫**文件描述符（fd）**。三条规则先立住：

- 进程启动时，0、1、2 已被占用，分别是标准输入、标准输出、标准错误；
- `open` 成功返回的永远是**当前最小的可用编号**；
- 用完 `close` 归还，号码随即被回收复用。

`ex01_open_write_read.cpp` 把这个闭环走了一遍，实测输出：

```
opened fd = 3
wrote 15 bytes
reopened fd = 3        ← 关掉后再开，又拿到 3：最小可用号规则
read 15 bytes: hello, syscall
```

`open` 的两个参数要说清：`flags` 用 `|` 拼装意图——`O_WRONLY/O_RDONLY/O_RDWR` 三选一是访问模式，`O_CREAT`（不存在则建）、`O_TRUNC`（存在则清空）、`O_APPEND`（总往尾部写）是修饰；只有带 `O_CREAT` 时才需要第三个参数 `mode` 给新文件的权限位（本章 0644，即属主读写、其他人只读）。fd 这套"一切皆文件"的抽象是 Linux 的地基，第 4 部分的 socket 也会回到这张桌子上——到那时你会发现收发网络数据和读写文件用的是同一副面孔。

## 3. read/write 的返回值：没有"一次到位"这回事

系统调用的返回值语义是本章第一个要交学费的地方。`read(fd, buf, n)` 的三种结局：

- **返回 > 0**：实际读到的字节数，**可能小于你申请的 n**（网络、管道里尤其常见，这叫部分读）；
- **返回 0**：读到尽头了（文件尾，或管道的写端已全部关闭）；
- **返回 -1**：出错，去看 errno。

`write` 同理：返回值是实际写出的字节数，可能只写了一部分。**结论：凡是要搬完整数据的地方，读写都必须写成循环**——读到 0 收工，写到全部出门为止。`solutions/ex03_copy_file.cpp`（练习 3 的答案）就是这个循环的标准形态，请对照细读。另外注意计数类型 `ssize_t` 是有符号的（为了能装 -1），拿无符号数接返回值是经典翻车点。

## 4. errno：先判返回值，再立刻存下它

失败的原因由全局变量 `errno` 给出（准确说，它是每线程一份的）。`ex02_errno.cpp` 演示了正确姿势与两个常见误读，实测：

```
open failed, errno = 2 (ENOENT = 2)
strerror: No such file or directory
perror says: No such file or directory        （perror 打到标准错误）
successful open, fd = 3, errno now = 22 (no longer 2: ...)
```

铁律三条，全部来自这段实测：

1. **errno 只在调用以失败收场时才有意义。**判定顺序永远是先看返回值（-1、NULL 等），再读 errno；反过来先看 errno 是新手最常见的误判来源。
2. **失败后立刻把 errno 存进局部变量。**本例最后一步是活证据：失败时 errno 是 2，可隔了几次 stdio 调用之后再读，它已经变成了 22——中间的函数有权改写它，连"我先 printf 一行日志再看 errno"这种无辜动作都会污染现场。
3. **成功调用不会把 errno 清零。**所以拿"errno 非零"当出错标志同样错误。报错文案有现成的两个工具：`strerror(errno)` 给字符串，`perror("前缀")` 直接连前缀带文案打到标准错误。

## 5. lseek：文件偏移与它的边界

普通文件支持随机访问：每个打开的文件都挂着一个"当前偏移"，`lseek` 负责搬动它，返回值是新偏移。`ex03_lseek.cpp` 在 16 字节的固定内容 `0123456789ABCDEF` 上实测：

```
from offset 10: ABCDEF          lseek 到 10 再读 6 字节
file size = 16                  lseek(fd, 0, SEEK_END) 的返回值即文件大小
last 4 bytes: CDEF              SEEK_END 回退 4 字节读尾
lseek on pipe: ret = -1, errno = 29 (ESPIPE = 29)
```

三种基准 `SEEK_SET`（从头）、`SEEK_CUR`（从当前）、`SEEK_END`（从尾，偏移可为负）配上返回值，随机读、求大小、读尾部（日志文件看最新几十行就是这么干的，练习 4 会让你亲手写）全齐了。最后一行是边界：管道这类**流**没有"位置"概念，`lseek` 必然失败并给出 `ESPIPE`——抽象再统一，也要认清每类对象的脾气。

## 6. 阻塞与非阻塞：read 的两种等待方式

默认的 `read` 是**阻塞**的：没数据时，内核把你的进程挂起，直到数据到达。`ex04_nonblock.cpp` 给管道读端用 `fcntl` 加上 `O_NONBLOCK` 后，非阻塞语义实测如下：

```
empty nonblock read: n = -1, errno = 11 (EAGAIN = 11)
after write: n = 4, data = ping
```

空管道读立刻返回 -1 且 `errno == EAGAIN`。请把这句话刻住：**EAGAIN 不是失败，是"现在没有数据，你先去忙别的"**——它是非阻塞编程的正常返回值，把 EAGAIN 当错误退出是这类代码最常见的 bug。非阻塞的意义在于：进程不必死等任何一路输入，可以轮着照看多路——这正是第四部分 epoll 的思想原型，本章先建立语感。顺带记住 `fcntl` 改标志的标准手法：`F_GETFL` 取现有标志、`|` 上新标志、`F_SETFL` 写回，直接写新值会把原有标志冲掉。

## 示例代码：构建与运行

```bash
cd examples
cmake -S . -B build
cmake --build build
cd build   # ex01、ex03 的数据文件生成在当前目录
./ex01_open_write_read
./ex02_errno
./ex03_lseek
./ex04_nonblock
```

核对要点：

- `ex01`：两次 open 的 fd 都是 3；写、读字节数均为 15，内容一致。
- `ex02`：失败时 errno 为 2（ENOENT），strerror/perror 文案一致；成功 open 之后 errno 已不是 2（实测 22，具体数值随环境与中间调用而变，只断言"不再是 2"）。
- `ex03`：偏移 10 处读出 ABCDEF；文件大小 16；尾 4 字节 CDEF；管道 lseek 返回 -1 且 errno=ESPIPE(29)。
- `ex04`：空管道非阻塞读为 -1/EAGAIN(11)；写入后读得 4 字节 "ping"。

> 验证记录：以上结果由作者在 Ubuntu 24.04 / GCC 13.3 环境下以 `-std=c++11 -Wall -Wextra` 构建实测（零警告），日期 2026-10-22。
