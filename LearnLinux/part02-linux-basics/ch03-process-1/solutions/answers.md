# 第 3 章 练习参考答案（第二部分）

## 练习 1

3 次无条件 fork 产生 2³ = **8 个进程**，hello 打印 **8 行**。

规则：每执行一次 fork，活着的进程数翻倍——第 k 次 fork 时每个现有进程都会再分出一个，所以 n 次无条件 fork 后是 2ⁿ 个进程，每个进程都执行到最后的 printf。

第二个变体：只有第一个 fork 出的子进程继续第二个 fork——进程数是 1（原父）→ fork 后 2 个 → 只有子进程再 fork 变 3 个：一共 **3 个进程**，hello 3 行。区分两者的关键是：fork 之后的代码由**当时活着的所有进程**继续执行，除非用返回值判断把某些进程挡在门外。

## 练习 2

成因：输出重定向到文件时，stdio 是**全缓冲**——"starting...\n" 打完后只是躺在父进程的缓冲区里，还没落盘。fork 把整个地址空间连同这块缓冲复制给子进程，于是父子手里各有一份 "starting..."。子进程用 `exit(0)` 退出时会冲刷自己那份；父进程 return 时也冲刷一份——同一内容写了两次。

两种修法（任选其一，原理不同）：

1. **fork 之前先冲刷**：在 printf 后、fork 前加 `fflush(stdout)`，让内容在分叉前就落盘，子进程继承到的缓冲是空的。
2. **子进程改用 `_exit`**：子进程退出时走 `_exit(0)`，不冲刷继承来的缓冲；子进程真有输出需求时先用 write 或手动 fflush 自己的内容。

（第三种视角：如果本意只是让程序自己打印，用 `write` 系统调用代替 printf 也绕开了缓冲，但日志代码通常还是前两种改法更顺手。）

## 练习 4

见 `ex04_two_children.cpp`（已编译验证，输出稳定地先 A=3 后 B=7，尽管 B 先结束）。

要点：`waitpid(指定 pid, ...)` 等的是特定孩子，与完成顺序无关；若用 `wait()` 则只能按完成顺序收（先收到 B），报告就得先通过返回的 pid 认人再对号入座——两种姿势都要会，本题练的是前者。

## 练习 5

(a) 僵尸占的是**进程表项**：PID 本身、退出状态、以及内核为它保留的少量统计信息。内存和 fd 都已随死亡释放，所以"占资源不多"；但 PID 是有限编号、进程表有上限，僵尸一只不占地方，一万只就能让 fork 全面失败。它的危险不在单只，在**只生不收的积累**。

(b) 症状链：僵尸数稳步上涨 → 进程数逼近上限（先是个别 fork 返回 EAGAIN/ENOMEM，新连接、新子任务起不来）→ 服务整体瘫痪，且此时连登录排查用的 shell 都未必起得来。系统性兜底：**用 SIGCHLD 信号驱动回收**——子进程结束时内核会给父进程发 SIGCHLD，处理逻辑里循环 `waitpid(-1, &status, WNOHANG)` 把已结束的全收走，不依赖业务代码记得调用。这是第 5 章的核心手法，本题先把动机建立起来。
