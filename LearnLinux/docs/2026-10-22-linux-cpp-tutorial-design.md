## 1. 背景与意图

学习者奕良：有基本 C/C++ 基础，但指针与模板薄弱；日常使用 Linux 熟练，但没有 Linux 开发经验。任职于广州小鹏汽车，岗位为智能座舱开发。

本教程的意图：以工作实战为导向，用一条循序渐进的主线，把他从"会用 Linux、写过一点 C++"带到"能独立开发较复杂的 Linux C++ 程序，并具备 CAN 总线、vsomeip、Fast DDS（小鹏封装为 xdds）、Vehicle HAL 相关的开发能力"。

## 2. 目标（Goals）

- 补齐 C++ 地基：指针与内存模型、模板，达到能读懂、写对的程度，而不是"见过"。
- 掌握 Linux 系统编程：文件与系统调用、进程、信号、线程、IPC、网络。
- 掌握并发编程：多线程、同步原语、并发安全，能识别并避免数据竞争与死锁。
- 掌握车载座舱通信技术：SocketCAN、SOME/IP + vsomeip、Fast DDS、Vehicle HAL 的属性模型与工作方式（在 Linux 上模拟全流程，不依赖 AOSP）。
- 沿途系统学习 C++11 → C++23 的主要新特性，并落实到示例代码中。
- 最终独立完成毕业项目"座舱信号网关"，把上述技术串成一条完整链路。

## 3. 非目标（Non-goals）

- 不进行 AOSP 全量源码编译与真机 HAL 联调；Vehicle HAL 只讲清结构与属性模型并在 Linux 上模拟。
- 不覆盖 AUTOSAR Adaptive Platform 的完整 ara 框架，只讲与其相关的概念接口。
- 不涉及 QNX、RTOS、嵌入式裸机开发。
- 不涉及 Qt/GUI 开发。
- 不以应试为目标，不做面试题式训练。

## 4. 反目标（Anti-goals，做到也算失败）

- 只讲 API 罗列、没有可编译运行的示例代码。
- 示例代码在目标环境（Ubuntu 24.04 + GCC 13）上编译不过或运行结果与讲解不符。
- 一次性倾倒全部内容，没有分批交付与反馈调整的闭环。

## 5. 约束

- 教程语言：中文；格式：Markdown；文档与示例代码统一存放于仓库 LearnLinux/ 目录。
- 学习者练习环境：公司自用开发机，无任何限制（sudo、外网拉取源码、加载内核模块均可）。因此环境搭建按基线对齐即可（列入第二部分第一章内容），CAN 实践可直接使用 vcan，第三方库可走源码构建。
- 工具链基线：Ubuntu 24.04、GCC 13、CMake、GDB，与作者（助手）的验证环境一致。
- C++ 标准：以 C++17 为工作基线；C++20 特性（concepts、协程、ranges、jthread 等）设专题章节；C++11/14 特性在地基与沿途章节中按历史顺序引入；C++23 点到成线为止。
- 所有示例必须先由作者在验证环境中实际编译、运行通过后再入库，并注明验证环境与运行结果。
- CAN 实践以 SocketCAN + 虚拟 CAN（vcan）为正规打法；作者验证环境若无法加载 vcan，则用等价的用户态模拟总线验证解码与分发逻辑，教程正文仍以 vcan 为准。
- 第三方库版本基线：vsomeip 3.x、Fast DDS 3.x，均从源码构建；具体小版本以产出对应章节时实测通过的版本为准并写明。
- xdds 是小鹏对 Fast DDS 的封装，本教程以开源 Fast DDS 为准教学；概念与建模方式通用，API 差异待日后对齐。

## 6. 方案选择

考虑过的三种组织方式：

- **方案 A（已选）：一条主线走到底。** 地基 → 系统编程 → 并发 → 网络/IPC → 车载专题 → 毕业项目，阶段项目逐段逼近毕业项目。取舍：体系完整、循序渐进；代价是车载专题出现较晚，用阶段项目与专题预告缓解。
- 方案 B：项目驱动，第一天就开工做信号网关，缺什么补什么。取舍：离工作最近，但地基（尤其指针、模板）容易补得零散，不符合"很详细、手把手"的要求，未选。
- 方案 C：双线并行，系统课主线 + 每段配一个车载小实验。取舍：看似兼顾，但两线互相牵扯、自学节奏易乱，未选。

学习者已确认选择方案 A。

## 7. 课程结构（预计 33～37 章 + 6 个项目）

### 第一部分 地基补强（约 6 章 + 阶段项目）
- 指针与内存模型（两章）：地址、解引用、多级指针、指针与数组、内存布局、野指针与悬垂指针。
- 引用、const 体系、函数指针与回调。
- 模板基础（两章）：函数模板与类模板、类型推导、特化与偏特化、模板的常见报错解读。
- RAII、智能指针与移动语义（C++11 线）。
- 阶段项目：手写一个模板动态数组容器，综合练指针+模板+RAII。

### 第二部分 Linux 开发起步（约 5 章 + 阶段项目）
- 工具链：GCC 编译流程、CMake 工程组织、GDB 调试、常用诊断命令。
- 文件与系统调用：fd、open/read/write、阻塞与非阻塞。
- 进程：fork/exec、僵尸与孤儿进程、wait、守护进程写法。
- 信号：signal/sigaction、信号安全函数、定时器信号。
- 阶段项目：多进程小工具（如简易日志收集：子进程写、父进程管）。

### 第三部分 并发与多线程（约 6 章 + 阶段项目）
- 线程模型：std::thread 与 pthread、线程生命周期。
- 同步原语：互斥锁、读写锁、条件变量、信号量。
- 原子操作与内存模型入门、无锁队列思想。
- 并发安全与死锁：数据竞争定位（TSan)、死锁的成因与规避。
- 线程池的设计与实现。
- C++20 并发设施：jthread、latch/barrier、协程初步。
- 阶段项目：线程安全的任务队列 + 日志库（后续毕业项目复用）。

### 第四部分 网络与 IPC（约 6 章 + 阶段项目）
- Socket 基础与 TCP/UDP 编程。
- I/O 多路复用：select/poll/epoll,Reactor 模式。
- Unix 域套接字与进程间通信全景（管道、消息队列、信号量集）。
- 共享内存：shm/mmap、同步问题、环形缓冲区设计。
- 序列化基础：结构体对齐、二进制协议设计、Protobuf 概念一瞥。
- 阶段项目：epoll 回显/聊天服务器 + 共享内存数据通道。

### 第五部分 车载专题（约 7 章）
- SocketCAN（两章）：CAN 帧结构、vcan 搭建、原始套接字收发、信号解码。信号解码以手写信号表为主线（位提取、大小端、缩放/偏移）；DBC 只讲文件格式与概念、以及真实项目中由 DBC 生成代码的路径，不实现完整的 DBC 解析器。
- SOME/IP 协议：报文结构、服务发现（SD）、请求/响应与事件。
- vsomeip 实操：routing manager、Offer/Request、事件订阅，写一对服务与客户端。
- Fast DDS（两章）：IDL 与类型生成、发布/订阅、发现机制；QoS 策略（可靠性、历史、截止期等）与实战调法。
- Vehicle HAL 模拟：Android Automotive 属性模型（Property ID、Area、值类型、变更模式），实现为一个独立进程的服务，经 Unix 域套接字对外提供属性的 get/set/subscribe 全流程；数据结构按真实 VHAL 的类型形状（如 VehiclePropValue 的字段构成）建模，以便日后对照 AOSP 代码阅读。

### 第六部分 毕业项目：座舱信号网关（约 3～4 章分步实现）
- 需求与架构：CAN 信号输入 → 解码 → 内部线程安全分发 → 三路输出。
- 实现一：CAN 接入与解码模块（SocketCAN/vcan，可切换模拟源）。
- 实现二：SOME/IP 服务发布 + Fast DDS 话题发布（同一信号双通道）。
- 实现三：HAL 风格属性接口层 + 并发安全与异常处理收尾、测试与复盘。

## 8. 章节模板（每章固定结构）

1. 本章目标（学完能做到什么）
2. 知识讲解（先讲"为什么"，再讲"怎么做"）
3. 示例代码（可编译运行，关键处中文注释；标注所用 C++ 标准特性）
4. 动手练习（由浅入深，附参考答案，答案默认折叠/独立文件）
5. 自测清单（勾选式，确认掌握程度）
6. 本章小结与下一章预告

## 10. 交付与节奏

- 无时间限制，不赶进度；以学扎实为准。
- 按"部分"分批交付到仓库；作者按计划连续产出下一部分，不必等学习者学完上一部分才动笔；学习者按自己节奏学习，以参考答案自查，遇到不懂之处随时反馈，作者据此调整后续章节的深度与示例选题。
- 练习、阶段项目与毕业项目均提供参考答案/参考实现供自查，不设提交批改流程。
- 章节粒度按"一次坐下来 1～2 小时能学完"切分。
- 每批交付在 README 进度表中登记（章节、验证状态、交付日期）。

## 11. 质量验证

- 每个示例在 Ubuntu 24.04 + GCC 13 下以 `-Wall -Wextra` 编译通过；并发章节示例额外用 ThreadSanitizer 跑一遍。
- 第三方库（vsomeip、Fast DDS）章节：作者先在本机完成源码构建与最小示例验证，再写安装步骤，步骤必须可照着复现。
- CAN 章节：vcan 可用时以 vcan 实测；不可用时用模拟总线验证解码与分发逻辑，并在章节验证记录中如实注明。

## 12. 作者已定的事项（学习者可推翻）

- C++17 为工作基线、C++20 设专题（理由：车载量产代码以 14/17 为主，20 是增量方向）。
- 章节粒度 1～2 小时、按部分分批交付（理由：匹配在职自学节奏，反馈闭环更短）。
- Vehicle HAL 只做 Linux 模拟、不碰 AOSP（学习者已确认）。
- VHAL 模拟做成独立进程服务（而非进程内库），接口按真实 VHAL 类型形状建模（理由：与真实 HAL 的进程边界一致、能顺带练 IPC，且日后看 AOSP 代码能对得上）。
- DBC 以手写信号表教解码原理为主线，不实现完整解析器（理由：C++ 生态缺少成熟的 DBC 解析库，自研解析器会喧宾夺主；真实工作中用的是生成工具）。
- DDS 以 Fast DDS 为准（学习者已确认 xdds 即其封装）。
- 设计文档放在 LearnLinux/docs/（服从"教程相关内容都进 LearnLinux"的仓库约定）。
