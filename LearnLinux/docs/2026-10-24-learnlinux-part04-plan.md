> 依据：主计划 Task 10 路线图（章节标题与顺序以路线图为准）。生产规则沿用既定约定：逐章确认制；**测试先行**（每章 `tests/run_tests.sh` 先于示例写定并跑红，再实现转绿，脚本随章入库）；C++11 为工作基线（网络与 IPC 示例均为 C++11 + POSIX API）；本部分示例的联网部分全部走回环（127.0.0.1），不依赖外网；凡是"客户端 + 服务器"的演示，一律做成单二进制（服务端跑在线程里），端口用 `bind(port 0)` + `getsockname` 动态取得，验收不依赖任何固定端口；凡涉及共享可变状态的线程示例，另以 TSan 构建复核（第 5 章起的硬性要求延续到本部分）。另有一条沙箱实情：作者环境禁 UDP（裸 UDP sendto 即报 EPERM，与代码无关），UDP 相关演示的验收脚本须做能力探测、不可用时明示跳过，正文如实标注未实测项（第 5 章 gdb 方法的先例）。

## Task 10.1 第 1 章 Socket 基础：地址、字节序与 TCP 最小闭环

- **目录**：`part04-network-ipc/ch01-socket-basics/`
- **目标**：会用 socket/bind/listen/accept/connect 建起 TCP 最小闭环；理解地址结构与字节序；掌握"字节流"语义下的收发循环。
- **知识点**：`sockaddr_in` / `sockaddr_storage` 与 `inet_pton` / `inet_ntop`；主机字节序与网络字节序（`htonl`/`htons`/`ntohl`/`ntohs`）；TCP 服务端四步（socket → bind → listen → accept）与客户端两步（socket → connect）；`send`/`recv` 的返回值语义（可能只传一部分、0 表示对端关闭、-1 查 errno）；`SO_REUSEADDR` 的用途；`EINTR` 与 close 的处理；单二进制演示的端口动态取得法（port 0 + getsockname）。
- **示例清单**：
  - `ex01_byteorder.cpp`：运行时判定主机字节序；`htonl(0x12345678)` 的网络字节恒为 `12 34 56 78`；`ntohl(htonl(x)) == x` 往返；核对：三行断言齐全（与主机字节序无关的断言写法）。
  - `ex02_tcp_echo.cpp`：服务端线程 + 客户端同进程，127.0.0.1 动态端口，客户端发 `hello socket`，服务端原样回显；核对：客户端收到完整回显、退出码 0；另以 TSan 构建复核（端口经值传递，服务端与客户端之间无共享可变状态，预期零报告）。
  - `ex03_send_recv_all.cpp`：`send_all` / `recv_all` 循环封装；客户端发 100000 字节模式数据，服务端循环收满并独立算校验和；核对：字节数与校验和双精确。
- **练习方向**：字节序问答（为什么网络字节序要统一、往返恒等式）；写代码：一问一答多轮回显（3 条消息逐条核对）；写代码：UDP 版 echo（SOCK_DGRAM，少了 listen/accept 两步）；思考：TCP"流"语义与下一章粘包的关系、send 返回小于请求长度意味着什么。

## Task 10.2 第 2 章 TCP/UDP 深入：粘包、消息边界与 UDP 语义

- **目录**：`part04-network-ipc/ch02-tcp-udp-deep/`
- **目标**：能解释并处理粘包；会用长度前缀与分隔符两种成帧法；理解 UDP 的数据报语义、适用场景与局限。
- **知识点**：粘包的本质（流无边界）与复现条件；成帧法一：4 字节长度前缀（网络字节序）+ 载荷；成帧法二：分隔符（换行）与它的适用边界；半包/粘包/超大包的读状态机；UDP：无连接、无流控、无重传、单包原子性（不超 MTU 时）、`sendto`/`recvfrom`；UDP 适用场景（DNS、实时音视频、游戏）与不适用场景；UDP 的"丢包、乱序、重复"在回环上难复现、在真实网络上必出现——回环实验的局限要写明。
- **示例清单**：
  - `bad_01_sticky.cpp`（反例）：服务端按"一次 recv = 一条消息"假设读，客户端连发 3 条短消息；核对：服务端收到的分块与发送分块不一致（粘在一起或被截断）——反例按"错得对"验收；
  - `ex01_length_prefix.cpp`：长度前缀成帧的收发，3 条消息逐条还原；核对：3 条内容逐条精确；
  - `ex02_delimiter.cpp`：换行分隔符成帧，含一条消息内嵌换行的处理说明（或转义约定）；核对：消息还原精确；
  - `ex03_udp_echo.cpp`：UDP 回显 + 单包大小边界演示（发 64KB 包看行为）；核对：小包往返精确，大包行为如实记录。
- **练习方向**：给成帧器加最大长度上限防内存炸弹；把长度前缀改成变长编码（varint）并对比；写代码：UDP 可靠化最小版（序号 + ACK + 超时重传，局域网内验证）；思考：TCP 粘包与 UDP 丢包，哪个更该由应用层兜底。

## Task 10.3 第 3 章 I/O 多路复用：select / poll / epoll 与 Reactor

- **目录**：`part04-network-ipc/ch03-io-multiplexing/`
- **目标**：会用 select、poll、epoll 做单线程多连接；理解三者演进的代价模型；能搭一个最小 Reactor。
- **知识点**：阻塞 IO 的瓶颈（连接数一多线程数跟着涨）；select 的 fd_set 与 FD_SETSIZE 上限、每次调用重建集合的代价；poll 的 pollfd 数组与无上限（但仍线性扫描）；epoll 的 epoll_create/epoll_ctl/epoll_wait、红黑树 + 就绪链表、水平触发（LT）与边缘触发（ET）、ET 下必须读到 EAGAIN；Reactor 模式（事件分发 + 回调）；epoll 与线程池的搭配形态（本部分阶段项目的前置）。
- **示例清单**：
  - `ex01_select_echo.cpp`：select 版多客户端回显（3 客户端并发）；核对：3 路消息各回各家；
  - `ex02_poll_echo.cpp`：同场景 poll 版；核对：同上，顺带对比代码量；
  - `ex03_epoll_lt.cpp`：epoll 水平触发版；核对：同上；
  - `ex04_epoll_et.cpp`：epoll 边缘触发版（非阻塞 fd + 读到 EAGAIN）；核对：同上，且把"ET 下漏读"做成反例小节（先读一次就停，说明下一轮事件不再来）；
  - `ex05_reactor.cpp`：最小 Reactor（epoll + 回调注册表）；核对：注册两个回调，各自被事件触发一次以上。
- **练习方向**：给 epoll 版加超时与空闲连接清理；LT 与 ET 的适用场景判断题；写代码：把 Reactor 的回调换成第 3 部分线程池投递；思考：epoll 为什么还需要线程池（回调里不能做重活）。

## Task 10.4 第 4 章 IPC 全景：管道、消息队列、信号量集、Unix 域套接字

- **目录**：`part04-network-ipc/ch04-ipc-overview/`
- **目标**：会按场景选 IPC 机制；掌握管道、System V 消息队列、信号量集、Unix 域套接字的用法与清理责任。
- **知识点**：IPC 选型表（方向、数据量、是否跨主机、是否持久、同步能力）；匿名管道 pipe（父子进程）与命名管道 FIFO（无亲缘进程，open 的阻塞语义）；System V 消息队列 msgget/msgsnd/msgrcv（类型化消息、权限与 ipcs/ipcrm 清理）；信号量集 semget/semop（P/V 操作、SEM_UNDO 的意义）；Unix 域套接字（路径名地址、SOCK_STREAM/SOCK_DGRAM、与 TCP 代码的复用度、文件清理）；各类 IPC 资源的泄漏与清理责任（谁创建谁清理、异常路径怎么办）。
- **示例清单**：
  - `ex01_pipe.cpp`：父子进程匿名管道，父发子收；核对：内容完整、子进程退出码 0；
  - `ex02_fifo.cpp`：命名管道两进程（fork 两路或线程模拟）通信；核对：内容完整、管道文件事后被清理；
  - `ex03_msgqueue.cpp`：消息队列按类型收（mtype 选择性接收）；核对：两类消息各归其位、队列事后被删除；
  - `ex04_semset.cpp`：信号量集互斥保护共享计数（与第 3 部分 mutex 对照）；核对：计数精确；
  - `ex05_unix_socket.cpp`：Unix 域流式套接字回显（与第 1 章 TCP echo 代码对比，改动点可数）；核对：回显精确、socket 文件事后被清理。
- **练习方向**：IPC 选型判断题（给场景选机制并说明理由）；写代码：FIFO 版生产者-消费者；思考：System V IPC 的"持久性"是一把双刃剑（崩溃后资源残留）；Unix 域套接字与 TCP 回环在性能与语义上的取舍。

## Task 10.5 第 5 章 共享内存：shm / mmap 与环形缓冲区

- **目录**：`part04-network-ipc/ch05-shared-memory/`
- **目标**：会用 POSIX 共享内存与 mmap 做零拷贝数据通道；会处理共享内存的同步问题；会实现一个可用的环形缓冲区。
- **知识点**：共享内存的本质（同一物理页映射进两个地址空间）与零拷贝收益；POSIX shm（shm_open/ftruncate/mmap/munmap/shm_unlink）与 System V shm 对照；mmap 文件映射与匿名映射的区别；共享内存的同步问题（裸读写即数据竞争，须配互斥/信号量或无锁结构）；进程间互斥（PTHREAD_PROCESS_SHARED 的互斥与条件变量）；环形缓冲区结构（读写指针、满/空判定、单生产者单消费者无锁版 vs 多生产者加锁版）；共享内存的生命周期与泄漏清理。
- **示例清单**：
  - `ex01_shm_basic.cpp`：父子进程经共享内存传一个结构体，子改父读；核对：值精确、shm 对象事后被 unlink；
  - `ex02_mmap_file.cpp`：mmap 文件读写（改文件内容、msync 落盘）；核对：文件内容如改后所示；
  - `ex03_ringbuffer_spsc.cpp`：单生产者单消费者无锁环形缓冲（原子读写指针 + 内存序说明）；核对：10000 条消息顺序完整、零丢失；
  - `ex04_ringbuffer_mpmc.cpp`：多生产者环形缓冲（互斥保护写指针，进程间互斥 PTHREAD_PROCESS_SHARED）；核对：多生产者总量精确、顺序可复核。
- **练习方向**：环形缓冲满/空判定的两种写法（留一格 vs 计数器）对比；写代码：共享内存版"日志通道"（生产者写、消费者批量落盘）；思考：共享内存 + 信号量 vs Unix 域套接字传数据，什么场景选前者；shm 泄漏的排查（/dev/shm 清单）。

## Task 10.6 第 6 章 序列化基础：对齐、填充与二进制协议设计

- **目录**：`part04-network-ipc/ch06-serialization-basics/`
- **目标**：会算结构体对齐与填充；会设计一个可演进的二进制协议；对 Protobuf 的位置有概念。
- **知识点**：对齐规则（成员按自身对齐值对齐、结构体按最大成员对齐、尾部填充）；`#pragma pack` 与 `__attribute__((packed))` 的代价（未对齐访问、跨平台风险）；直接发结构体内存的四个坑（填充字节未定义、字节序、指针成员、版本演进）；二进制协议设计要素（魔数、版本、长度、类型、校验和、兼容性策略）；TLV 编码；Protobuf 概念一瞥（.proto、字段编号、向后兼容的规则、与手写协议的取舍）；序列化与第五部分 SOME/IP、Fast DDS 的 IDL 的呼应（概念先行，实操在后）。
- **示例清单**：
  - `ex01_alignment.cpp`：打印三个结构体的 sizeof 与成员偏移，验证对齐规则；核对：数值与手算一致；
  - `bad_01_raw_struct.cpp`（反例）：直接 `send(&struct)` 跨"版本"（加字段）通信，旧接收方读出错误值；核对：错得对，且说明错在哪一字节；
  - `ex02_tlv_protocol.cpp`：手写 TLV 编解码（类型-长度-值，长度网络字节序），新字段可忽略；核对：旧解码器读新消息时未知字段被跳过、已知字段精确；
  - `ex03_protobuf_peek.cpp`：概念演示——若环境有 protoc 则生成并跑通一次最小 .proto 收发；若无则以文字 + 伪代码演示并标注环境要求（不硬编造输出）。
- **练习方向**：手算对齐题（给结构体算 sizeof 与偏移）；给 TLV 加校验和与版本号；思考：为什么"直接发结构体"在座舱信号网关里是禁区；Protobuf 字段编号为什么不能复用。

## Task 10.7 阶段项目：epoll 服务器 + 共享内存数据通道

- **目录**：`part04-network-ipc/project-epoll-shm/`
- **形态**：任务书 + 骨架 + 验收脚本（先行）+ 参考实现，与第三部分阶段项目同构。
- **规格要点**：
  - epoll 服务器：单线程 epoll（LT）接多客户端，协议为第 2 章长度前缀成帧；每个连接有独立读缓冲与状态机；空闲超时清理；把收到的消息原样回显并计数。
  - 共享内存数据通道：服务器把每条消息同时写入第 5 章的环形缓冲区（共享内存），另起一个消费者进程（或线程）从环形缓冲读出并落盘统计；双通道数据一致性可验收。
  - 复用：线程池（第 3 部分项目）用于耗时回调；Logger（第 3 部分项目）用于服务器日志；BlockingQueue 用于服务器内部任务分发——三个接口的复用本身就是验收项之一。
- **验收要点**：10 客户端并发各发 100 条消息，回显逐条精确、服务器统计计数精确；共享内存通道落盘行数与回显数一致；空闲连接超时后被清理；全程 ASan+UBSan 与 TSan 双构建零报告；骨架版（无成帧状态机、无共享内存通道）必须被判下。
- **与毕业项目的关系**：网关的网络接入层（epoll + 成帧）与进程间数据通道（共享内存环形缓冲）即用本项目的两件套，不再另写。
